# Maintain Project contract

`inputs` declares inventory, window, providers and allowed actions. Use exact source timestamps in the output even when the initial request names a relative window.

`result.coverage` records each operational area, timestamp, evidence and limitations. Include unavailable areas rather than dropping them. `findings` separates confidence from severity. `maintenance_actions` names targets, impact, recovery and authorization state. `next_review` is null unless a future review time was actually agreed; even a proposed time is not a scheduled automation.

Record gaps from retention, missing permissions, telemetry interruptions or unavailable providers. Cost figures need currency, interval, estimate/actual distinction and source evidence in the referenced report. Scripts validate structure and cited proof, not the completeness of provider coverage.
## Envelope and evidence

JSON uses exact fields declared by `assets/contract.json`, UTF-8, `schema_version: 1`, unique IDs, no duplicate keys and no nonfinite numbers. The input envelope contains `project_id`, `request`, `repository` (path/revision/working_tree_sha256 or null), `ledger` and `definition` (path/SHA-256 or null), `constraints`, `sources` and domain `inputs`. Each source has `{id, path, sha256}`. Paths resolve from the input JSON directory. Keep private inputs outside the public skill folder.

Output contains the same project ID, exact skill name, canonical `input_sha256`, `status`, `summary`, retained constraints, evidence, blockers and domain `result`. Evidence entries are `{id, kind, reference:{path,sha256}}`, with kind command, artifact or observation. Command proof is generated by `workflow.py record`; observations are JSON `{kind:"ct-observation.v1", source, observed_at, statement, limitations}` with a timezone-aware observation timestamp. Artifact evidence is an actual inspectable file. References are checked against file bytes, not trusted from declarations.

The supplied definition must validate against the supplied ledger, project scope and constraints. A ready report requires a ready project definition; missing prerequisites can be represented by a valid blocked report. Blocked output includes explicit reason and smallest next action. Ready means the requested specialist stage completed, with the limitations described here. It never implies production safety or customer acceptance.

Packaged example input/output are deliberately blocked synthetic examples: they demonstrate truthful handling of missing definition and evidence. Their empty sources are not a pattern for claiming a completed assessment. Never replace missing evidence with arbitrary hashes or fabricated observations.

Scripts validate structural invariants, source/requirement/evidence references, file hashes, input binding and applicable readiness rules. They do not establish that a citation supports a statement or that a source is trustworthy. Inspect evidence before reporting conclusions.

## Current source binding

Use `python3 <skill>/scripts/workflow.py inspect-repository <repo>` to obtain
`{path, revision, working_tree_sha256}` when a repository is supplied. Keep proof
files outside that repository or in an ignored directory. After authorized code
changes, retain the earlier intake as history, refresh the current intake source
fingerprint, and bind the output to its new digest. Preserve the original scope,
constraints and interview answers. Passing checks must match this final source
state; an earlier failing reproduction can retain its historical source binding.
